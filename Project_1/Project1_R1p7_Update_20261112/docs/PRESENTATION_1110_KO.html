발표에서 쓸 해석

아래 비교는 int8_fastv2 기준이다.

  • EX가 T에서 이긴다. EX는 single보다 cycle이 14.3% 많지만 주기가 2.36배 짧다(3.82 → 1.62 ns). T는 2.06배 짧다.
  • ID는 cycle이 적어도 주기에서 진다. ID는 EX보다 cycle이 6.0% 적지만 주기가 45.7% 길어서 T가 36.9% 길다(1.3980 대 1.0210 µs).
  • P는 EX가 가장 나쁘다. single의 2.20배다. 클럭이 빨라진 만큼 초당 스위칭이 늘기 때문이다.
  • 한 번 실행에 드는 에너지(P × T)는 셋이 비슷하다. single 14.74 nJ, ID 16.04 nJ, EX 15.73 nJ. 채점 항목은 아니고 위 표에서 계산한 값이다.
  • 256 구간 프로그램을 고른 이유. EX에서 int8_opt64v2 대신 int8_fastv2를 쓰면 A가 22.8%, P가 30.0% 늘지만 T가 18.9% 줄고 T 배점이 A·P의 두 배다. 다만 v2로 차이가 좁혀져서(표 내 점수 19.47 대 18.85), A·P가 아주 작은 팀이 있으면 순서가 바뀔 수 있다.
  • v2의 효과는 분기가 많은 프로그램에서 크다. int8_opt64는 EX에서 5.4% 줄었고, 이미 분기를 펼쳐 놓은 int8_fast는 0.9%만 줄었다.

주기를 정한 방법

후보 주기마다 공식 synth/run_ppa.tcl과 같은 순서·같은 compile로 합성해 setup·hold slack이 둘 다 0 이상인 가장 짧은 주기를 골랐다. compile_ultra는 쓰지 않았다. 고른 주기로 공식 flow를 돌렸을 때 slack이 탐색 값과 소수 넷째 자리까지 같았다.

1차 탐색(0.05 ~ 0.30 ns 간격)에서 통과한 최소 주기는 single 3.90, ID 2.40, EX 1.70 ns였고, 그 아래를 0.02 ns 간격으로 다시 탐색했다.

말할 때 조심할 것

  • 숫자는 공개 16 case 기준이다. 공식 성적은 비공개 8개를 더한 24 case로 따로 나온다.
  • 타이밍 여유가 EX 2.6 ps, single 0.8 ps, ID 0.3 ps다. RTL을 한 줄이라도 고치면 주기를 다시 탐색해야 한다.
  • R1.3a 이전 flow(compile_ultra, 옛 SDC)로 얻은 숫자(예: 2.1 ns, 1.7 ns)는 조건이 달라 이 표와 섞어 쓰면 안 된다. PRESENTATION_COMPARE_KO.md가 그 옛 자료다.
  • 기본 8명령만 구현했다. 선택 확장 명령과 M 확장은 쓰지 않았다.

서버에서 재현하기

방법이 두 가지다. A는 과제 공식 스크립트 2줄이고, B는 같은 일을 수업에서 쓴 명령(vcs_queue, simv, dc_shell_queue와 W06·W07 DC 명령)으로 한 줄씩 하는 방법이다. 둘 다 이 작업 폴더(Project_1/Project1_R1p7_Update_20261112)에서 실행한다. B의 1~5단계는 공식 스크립트가 실제로 실행하는 명령과 같고, 6단계 계산은 서버 결과 파일로 공식 결과와 같은 값이 나오는지 확인했다.

한 줄씩 입력한다. Error / Fatal / FAIL이 나오면 멈추고 그 화면을 공유한다.

R1.7 스크립트가 서버의 /usr/bin/python3.12와 vcd2saif 경로를 스스로 잡는다. 다른 프로그램을 재기 전에 results reports logs를 따로 묶어 보관한다(다음 실행이 덮어쓴다). 최종 제출용은 int8_fastv2를 마지막에 돌린 결과다.

B는 수업 명령만 쓰므로 vcd2saif가 PATH에 없으면 먼저 export PATH=/opt/eda/synopsys/products/syn/V-2023.12-SP5/bin:$PATH.

B1. 컴파일 — Linux 터미널 (VCS)

vcs_queue -full64 -timescale=1ns/1fs -top TB_TOP -f synth/rtl.f \
  sim/mem/IMEM.v sim/mem/DMEM.v sim/MEMORY_POWER.v sim/TB_TOP.v \

B2. 16 case 실행 — Linux 터미널

for f in cases/*.json; do
  c=$(basename $f .json)
  ./build/simv +PROGRAM=programs/int8_fastv2.hex \
    +DATA=cases/${c}_dmem.hex +EXPECTED=cases/${c}_expected.hex \
    +F_MHZ=617.283950617 +VCD=build/$c.raw.vcd -l logs/$c.log
done
grep -h "PASS TB_TOP" logs/*.log | wc -l    # 16
grep -h "DONE at cycle" logs/*.log          # case별 cycle (586 ~ 682)

F_MHZ는 1000 / 1.62. TB가 이 주파수로 클럭을 만들고, reset 뒤부터 DONE store까지 cycle·load·store를 세서 로그에 MEMORY_PPA, ACTIVE_WINDOW 줄로 남긴다.

B3. 실행 구간만 SAIF로 — Linux 터미널

for f in cases/*.json; do
  c=$(basename $f .json)
  read s e < <(grep -o 'ACTIVE_WINDOW.*' logs/$c.log | sed 's/[^0-9. ]//g')
  python3.12 -c "import sys; sys.path.insert(0,'tools'); from trim_vcd import trim; trim(sys.argv[1], sys.argv[2], float(sys.argv[3]), float(sys.argv[4]))" \
    build/$c.raw.vcd build/$c.active.vcd $s $e
  vcd2saif -input build/$c.active.vcd -output build/$c.saif
done
ls build/*.saif | wc -l                     # 16
echo "set P1_CASES {$(ls cases/*.json | xargs -n1 basename | sed 's/\.json$//' | tr '\n' ' ')}" > synth/case_list.tcl

VCD에서 reset·대기 시간을 빼고 DONE까지의 구간만 남겨야 전력 평균이 공식과 같아진다. 이 자르기만 과제 배포 도구 tools/trim_vcd.py를 쓴다. vcd2saif는 과제 공통 flow 문서(docs/COMMON_FLOW_KO.md)의 명령이다.

B8. T·A·P 계산 — Linux 터미널

# case별 cycle, load, store, CPU 전력(dynamic + leakage, mW)
for f in cases/*.json; do
  c=$(basename $f .json)
  m=$(grep -o 'MEMORY_PPA cycles=[0-9]* LOAD=[0-9]* STORE=[0-9]*' logs/$c.log | sed 's/[^0-9 ]//g')
  p=$(grep -E 'Total Dynamic Power|Cell Leakage Power' reports/$c/power.rpt |
      awk '{sub(/.*= */,""); k=($2=="W")?1000:($2=="mW")?1:($2=="uW")?0.001:($2=="nW")?1e-6:1e-9; s+=$1*k} END{print s}')
  echo $c $m $p
done > results/hand_ppa.txt
cat results/hand_ppa.txt

# T = 평균 cycle / f,  A = CPU + IMEM 256 + DMEM,  P = CPU(cycle 가중) + 메모리 동적 + 메모리 정적
A_CPU=$(grep 'Total cell area' reports/cpu_area.rpt | awk '{print $NF}')
awk -v f=617.283950617 -v acpu=$A_CPU '{n++; cy+=$2; acc+=$3+$4; pw+=$5*$2} END{
  Pc=pw/cy; Pd=f/1000*(7.00+12.97*acc/cy); Ps=0.020*(27352.30+50667.68)/1000;
  printf "mean_cycles %.4f   T %.6f us\n", cy/n, cy/n/f;
  printf "A  cpu %.2f + IMEM 27352.30 + DMEM 50667.68 = %.2f um2\n", acpu, acpu+27352.30+50667.68;
  printf "P  cpu %.4f + mem_dyn %.4f + mem_static %.4f = %.4f mW\n", Pc, Pd, Ps, Pc+Pd+Ps}' results/hand_ppa.txt

이렇게 나오면 공식 결과와 같다.

mean_cycles 630.2500   T 1.021005 us
A  cpu 22322.99 + IMEM 27352.30 + DMEM 50667.68 = 100342.97 um2
P  cpu 8.8303 + mem_dyn 5.0197 + mem_static 1.5604 = 15.4104 mW

메모리 상수는 계약서 값이다. int8_fastv2는 193 word라 IMEM 256 구간(면적 27352.30 µm², 접근 7.00 pJ)이고, DMEM은 접근당 12.97 pJ, 정적 전력은 0.020 mW / 1,000 µm². 다른 프로그램을 재면 programs/ 이름과 IMEM 구간 상수를 바꾼다.

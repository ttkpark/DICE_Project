## 2. 첫 번째 회로: 둘 중 하나 고르기

MUX는 **두 입력 중 하나를 골라 출력하는 회로**입니다.

| 이름 | 뜻 |
|---|---|
| A | 첫 번째 입력. 0 또는 1 |
| B | 두 번째 입력. 0 또는 1 |
| S | 어떤 입력을 고를지 정하는 값 |
| Y | 선택한 결과가 나오는 출력 |

규칙은 두 줄입니다.

- S가 0이면 Y에 A를 내보냅니다.
- S가 1이면 Y에 B를 내보냅니다.

예를 들어 A=0, B=1이면 S=0일 때 Y=0, S=1일 때 Y=1입니다.

## 3. 정답 파일 열어 보기

수업 서버에 로그인한 뒤 터미널에서 아래 명령을 **한 줄씩** 입력하세요.
`#` 뒤의 한글은 설명입니다. 함께 입력해도 됩니다.
교강사가 파일을 `~/DICE/W03`에 준비한 상태를 기준으로 합니다.
다른 위치에서 실습한다면 첫 번째 명령의 경로를 바꾸세요.

```bash
cd ~/DICE/W03/todo/lesson # 수업 실습 폴더로 이동
pwd # 지금 어느 폴더인지 확인
cat ../../answer/lesson/rtl/01_mux2.v # 정답을 화면에 표시
```

정답에서 이 부분을 찾아보세요.

```verilog
always @(*) begin
    if (S == 1'b0) begin
        Y = A;
    end
    else begin
        Y = B;
    end
end
```

말로 읽으면 “입력이 바뀌면 다시 계산한다. S가 0이면 A, 그렇지 않으면 B를 Y에 넣는다”입니다.

| 코드 | 쉽게 읽기 |
|---|---|
| `always @(*)` | 이 안에서 사용하는 입력이 바뀌면 다시 계산 |
| `if` / `else` | 조건이 맞으면 / 그렇지 않으면 |
| `==` | 두 값이 같은지 비교 |
| `=` | 오른쪽 값을 왼쪽에 넣기 |
| `1'b0` | 한 칸짜리 이진수 0 |
| `begin` / `end` | 여기부터 / 여기까지 한 묶음 |
| `;` | 대입 문장이 끝났다는 표시 |
| `//` | 뒤쪽은 사람을 위한 설명 |

`module`은 회로의 시작, `endmodule`은 끝입니다.
`input`은 입력, `output`은 출력입니다.
이 예제의 `output reg Y`는 “Y를 always 안에서 대입한다”는 선언입니다.
`reg`라는 글자만 보고 기억 장치라고 생각하지 않아도 됩니다.

## 5. 컴파일하고 실행하기

컴파일은 “작성한 코드를 실행할 수 있는 파일로 바꾸기”입니다.
그다음 실행하면 검사 코드가 입력을 넣고 결과를 확인합니다.
아래의 긴 명령은 그대로 복사해도 됩니다.

```bash
mkdir -p build # 실행 파일을 담을 폴더 만들기
bash 01_run_mux2.sh # VCS로 컴파일·검사하고 FSDB 저장
bash 01_view_mux2.sh # Verdi에서 기존 회로와 파형 확인
```

**컴파일에서 오류가 나오면 멈추고 코드를 먼저 고치세요.**
오류 없이 끝나면 실행 명령으로 넘어갑니다. 컴파일 성공 시 아무 글자도 나오지 않을 수 있습니다.

아래 문장이 나오고 `FAIL:` 문장이 없으면 성공입니다.

```text
PASS: MUX2
```

`FAIL:`은 검사에서 기대한 값과 다른 값이 나왔다는 뜻입니다.
아직 TODO를 고치지 않은 파일에서 FAIL이 나오는 것은 정상입니다.
코드를 고쳤다면 **컴파일 → 실행 두 명령을 다시** 입력하세요.
실행만 하면 수정 전 파일이 실행될 수 있습니다.

## 6. 입력을 직접 한 번 바꿔 보기

```bash
vim tb/01_tb_mux2.v # 입력을 넣는 검사 파일 열기
```

첫 번째 검사에 있는 `A = 1'b0;`을 `A = 1'b1;`로 바꿔 보세요.
그 검사는 S=0이므로 이제 Y도 1이어야 합니다.
바로 아래 `if (Y !== 1'b0)`도 `if (Y !== 1'b1)`로 바꾸세요.
기대값을 바꾸지 않으면 맞는 회로도 FAIL이라고 표시됩니다.
그 검사 옆 설명과 FAIL 문장의 A 값도 1로 맞추면 결과를 읽기 쉽습니다.

저장하고 앞의 컴파일과 실행 명령을 다시 입력하세요.
검사 코드의 `#10`은 “계산될 시간을 잠깐 기다리기”이고,
`!==`는 “기대값과 다른가?”를 확인합니다. 회로 파일에는 `#10`을 넣지 마세요.
확인이 끝나면 방금 바꾼 부분은 원래대로 되돌리고 저장하세요.

## 7. 다음 회로: 표를 그대로 코드로 옮기기

디코더는 **입력 번호에 해당하는 출력 하나만 1로 켜는 회로**입니다.
`SEL[1:0]`은 2칸, `Y[3:0]`은 4칸짜리 이진수입니다.

| SEL | Y |
|---|---|
| 00 | 0001 |
| 01 | 0010 |
| 10 | 0100 |
| 11 | 1000 |

`rtl/02_dec2_if.v`와 `rtl/03_dec2_case.v`에서 TODO 옆의 `0000`을 표에 맞게 바꾸세요.
두 파일은 같은 일을 서로 다른 문법으로 표현합니다.
`case`는 “입력값이 표의 어느 행에 해당하는지 찾아서 그 값을 넣기”입니다.
`default`는 표에 해당하는 값이 없을 때입니다. 이 줄은 제공된 그대로 둡니다.

파일을 여는 명령부터 실행 명령까지는 [README의 수업 실행 순서](01_README.md#수업-예제-실행-순서)에 있습니다.
성공하면 `PASS: LOOKUP`이 나옵니다.

## 8. 일부러 틀린 코드 고쳐 보기

먼저 README의 `tb_fix` 컴파일과 실행 명령으로 수정 전 결과를 보세요.
이후 `rtl/06_mux_fixed.v`에서 두 군데를 고칩니다.

1. `always @(A or S)`를 `always @(*)`로 바꿉니다. B만 바뀌어도 다시 계산해야 합니다.
2. `if (S) Y = B;` 다음에 `else Y = A;`를 넣습니다. S=0일 때의 값도 정해야 합니다.

`if (S)`는 이 예제에서 S=1인지 확인하는 표현입니다.
수정한 파일을 다시 컴파일하고 실행하면 `PASS: FIXED`가 나와야 합니다.

화면의 `BAD_SENSITIVITY`와 `BAD_ASSIGNMENT`는 일부러 틀리게 만든 원본입니다.
이 값은 계속 틀려도 됩니다. 내가 고친 회로는 `FIXED`라는 이름으로 표시됩니다.
FIXED가 **0 → 1 → 0**으로 바뀌는지 보세요.

첫 번째 오류는 “B가 바뀐 것을 놓침”, 두 번째 오류는 “새 값을 넣지 않아 이전 값이 남음”입니다.
두 번째처럼 이전 값을 유지하는 회로를 래치라고 부릅니다.

## 9. 수업 후: 더한 숫자를 두 자리로 표시하기

한 번에 모두 하지 말고 **한 파일 완성 → 그 파일 검사** 순서로 진행하세요.
각 파일의 정답은 `answer/checkpoint/rtl`에 있습니다.
[README의 검사 블록 실행 순서](01_README.md#검사-블록-실행-순서)를 한 단계씩 따라갑니다.

| 순서 | 내 파일 | 하는 일 | 성공 표시 |
|---|---|---|---|
| 1 | 07_add4.v | 두 수를 더하기. 15+15=30도 담을 수 있어야 함 | PASS: ADD4 |
| 2 | 08_bin5_to_bcd.v | 27을 십의 자리 2와 일의 자리 7로 나누기 | PASS: BIN5_TO_BCD |
| 3 | 09_bcd_to_7seg.v | 숫자 하나를 표시할 막대 7개의 켜짐/꺼짐 정하기 | PASS: BCD_TO_7SEG |
| 4 | 10_w03_top.v | 위 회로들을 직접 연결하기 | PASS: W03_TOP |

4비트에는 0~15만 담을 수 있으므로 합계에는 5비트를 사용합니다.
BCD는 여기서 “십진수의 각 자리를 각각 4비트에 담은 값”입니다.
7-segment는 숫자를 만드는 막대 7개입니다. 이번 기준에서는 0을 보내면 막대가 켜집니다.
숫자별 표는 README에 있으므로 외우지 말고 표를 보고 작성하세요.

마지막 TOP 연결은 직접 해 보는 과제라서 answer에도 완성 답이 없습니다.
먼저 앞의 세 검사를 통과한 뒤 시작하세요. 연결 전 TOP 검사가 FAIL인 것은 정상입니다.
최종적으로 0+0은 00, 3+5는 08, 7+3은 10, 15+1은 16, 15+15는 30으로 표시되어야 합니다.

## 막히면 여기부터 확인하세요

| 보이는 상황 | 먼저 할 일 |
|---|---|
| 폴더가 없다고 나옴 | `cd`에 입력한 위치와 교강사가 안내한 배포 위치 확인 |
| `iverilog` 또는 `vvp`가 없다고 나옴 | 교강사에게 실습 도구 설치 확인 요청 |
| `syntax error` | 표시된 줄과 바로 앞줄의 세미콜론, 괄호, begin/end 확인 |
| 고쳤는데 결과가 그대로임 | 저장했는지 확인한 뒤 컴파일부터 다시 실행 |
| 출력에 x 또는 z가 나옴 | 출력에 값을 넣었는지, 연결을 빠뜨렸는지 확인 |
| blank에서 실행이 안 됨 | 처음에는 todo 폴더에서 실습 |

다 끝나면 조교에게 실행 결과를 보여 주고, “S가 0일 때 왜 A가 나오는지”부터 자기 말로 설명해 보세요.

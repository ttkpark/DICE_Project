## 실행 도구와 결과

3주차처럼 `bash 01_run_addsub.sh`로 VCS 검사 후 `bash 01_view_addsub.sh`로 Verdi를 엽니다.
서버에서 확인한 명령은 `vcs_queue`, `verdi_sub`입니다. FSDB와 VCD를 함께 저장합니다.
파일리스트(.f)는 컴파일할 소스 목록, FSDB/VCD는 실행하면서 기록한 파형입니다.
코드를 수정하면 run을 다시 실행해야 합니다. view는 재계산하지 않습니다.
`-R`에 시뮬레이션이 포함되어 있으므로 생성된 simv를 따로 실행하지 마세요.
실패하면 다음 단계로 넘어가지 말고 최초 오류부터 확인하세요.
`$finish`는 FAIL이어도 종료코드 0일 수 있습니다. 최종 PASS와 FAIL 부재를 함께 보세요.

## 수업 범위

ADD·SUB·AND·OR·XOR·signed SLT·SLL·SRL의 8개 연산입니다.
RV32I 연산의 교육용 부분집합이며 전체 CPU나 명령어 해독기가 아닙니다.
3비트 제어코드는 수업 내부 약속이며 opcode/funct3가 아닙니다.
클록·리셋·플립플롭은 다음 주 범위입니다. 이번 필수 실습에는 FPGA/Quartus가 없습니다.
`reg`는 always에서 값을 대입하는 선언이며 그 자체가 저장장치를 뜻하지 않습니다.

서버 로그인·파일 배포·편집기 준비가 끝난 상태에서 시작. 30분은 **완성 예제 따라 하기와 개념 설명**에 사용. 빈칸 12곳 작성과 조교 검사는 이후 실습 시간에 진행하며, 이를 30분 안에 모두 끝내도록 요구하지 않음.

| 시간 | 학생 활동 | 해당 장면에서 설명할 내용 |
|---|---|---|
| 0~4분 | 완성 예제 실행, `a`, `b`, `alucontrol`, `result` 위치 확인 | ALU는 입력과 연산 번호에 따라 출력이 바뀌는 조합회로 |
| 4~11분 | `3+5`, `8-3`, `5-5` 실행. ADD에서 A만 변경하여 재실행 | `A + B`와 `A + (~B) + 1`, 32비트 결과, Zero |
| 11~17분 | A=`0A`, B=`0C`로 고정하고 AND→OR→XOR 실행 | 비트별 연산, `case` 한 행과 연산 하나의 대응 |
| 17~24분 | `FFFFFFFF < 1`, `80000000 < 1`의 결과 관찰 | signed 해석, 감산 결과의 부호만으로 비교하면 틀리는 경우 |
| 24~28분 | B=`1`, `1F`, `24`로 시프트 실행 | 거리 1·31·4, `b[4:0]`, 오른쪽 빈자리의 0 채움 |
| 28~30분 | TODO 파일·예제 위치 확인, 체크포인트 검사 방법 확인 | 빈칸 12곳, 결과와 Zero 동시 검사, PASS 판정 |
| 이후 실습 | TODO 작성 → 전체 검사 → 조교 확인 | lesson 예제 참고, 필요 시 실패한 사례 한 개만 파형 확인 |

수업에서는 overflow 공식을 유도하지 않음. 이미 제공된 식을 사용하여 틀리기 쉬운 예 한 개를 확인하고, 유도 과정은 부록으로 분리. 32비트 숫자 전체를 이진수로 전개해 외우도록 요구하지 않음.

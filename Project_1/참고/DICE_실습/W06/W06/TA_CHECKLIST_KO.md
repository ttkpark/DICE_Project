# W06 조교 확인표

기본은 `todo/checkpoint/rtl/REGFILE.v`입니다. 정답 참고는 허용하며 학생 본인의 실행·관찰·설명을 확인합니다.

- [ ] 인터페이스가 REGFILE / CLK / RESET / WE3 / A1·A2·A3 / WD3 / RD1·RD2로 유지됨.
- [ ] T1~T6을 완성했고 RF는 32개 × 32비트 배열임.
- [ ] 두 lesson을 실행하여 읽기 2개·쓰기 1개의 의미를 설명함.
- [ ] 조교 앞에서 README의 `vcs_queue` 명령을 현재 소스로 재실행, 14/14 PASS 확인.
- [ ] README의 `verdi_sub` 명령으로 방금 생성한 FSDB를 열고 아홉 포트 신호 확인.
- [ ] C05의 WE3=0은 0으로 지우는 것이 아니라 저장값 유지임을 설명함.
- [ ] C08 71ns의 이전 값 10과 C09 76ns의 새 값 99를 구분함.
- [ ] C06은 51ns에 출력이 교환되며 다음 55ns 상승 에지를 기다리지 않음.
- [ ] C10/C11에서 읽기 포트가 달라도 x0=0임을 확인함.
- [ ] C13의 RESET이 112ns에 올라 113ns 검사에서 이미 0임을 확인함.
- [ ] 소스에서 non-blocking `<=`, RESET 우선순위, 비동기 이벤트 목록 확인.
- [ ] 소스에서 x0 쓰기 금지와 x0 출력 0 고정을 **각각** 확인.
- [ ] “읽기는 주소에 즉시 반응하고, 쓰기는 허용된 상승 에지에서 저장한다”를 설명함.

학생 TB는 대표 주소 검사입니다. x0 보호 둘 중 하나를 없애도 외부 출력이 같을 수 있어 두 보호를 각각 소스로 검사합니다. `=`와 `<=`의 차이도 기능 PASS만으로 판정하지 않습니다.

## 별도 합성 레슨 — 비채점

합성은 [레슨 3](todo/lesson/03_synthesis/README_KO.md)에서 진행합니다. 레슨 1·2에는 시뮬레이션과 파형만 있습니다. 체크포인트의 기능 검사는 위 기준 그대로입니다.

- [ ] DC를 켜고 환경 설정만 `source setup.tcl`로 읽음.
- [ ] `synth.tcl`의 명령을 한 줄씩 입력하고 Error/Fatal/FAIL이면 멈춤.
- [ ] ns/fF 단위를 확인한 뒤 제공 조건을 입력함.
- [ ] check_design 성공과 is_mapped=true를 확인함.
- [ ] 셀 연결 하나, Total cell area, slack 부호를 찾음.
- [ ] 결과를 저장하고 exit하여 큐 슬롯을 반환함.

학생에게 해시 확인·자체 성공 마커·합성 보고서 제출을 요구하지 않습니다. 합성 환경 오류나 음수 slack 때문에 REG 통과를 취소하지 않습니다.

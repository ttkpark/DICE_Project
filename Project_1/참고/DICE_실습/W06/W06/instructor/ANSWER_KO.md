## 고정 14개 검사와 파형

두 출력은 매 그룹마다 `!==`로 각각 검사합니다. 출력에 X/Z가 있어도 통과하지 않습니다. 시간은 ns이며 로그의 `%t` 표시는 시뮬레이터 정밀도(1ps) 기준으로 보일 수 있습니다.

| 검사 | 검사 시점(ns) | 조건과 의도 | RD1 | RD2 |
|---|---:|---|---|---|
| C01 | 3 | 2ns에 RESET 활성화, 첫 상승 에지 전 x1/x31 초기화 | 0 | 0 |
| C02 | 16 | RESET=1, WE3=1, x1←99 시도: 리셋 우선 | 0 | 0 |
| C03 | 26 | 리셋 해제 후 25ns 에지에서 x1←10 | 10 | 0 |
| C04 | 36 | 35ns 에지에서 x2←20, x1 유지 | 10 | 20 |
| C05 | 46 | WE3=0, x1←99 입력으로 45ns 에지 통과 | 10 | 20 |
| C06 | 51 | A1=2, A2=1, 다음 상승 에지 전 교환 | 20 | 10 |
| C07 | 61 | A1만 31로 변경, RD2 독립성 | 0 | 10 |
| C08 | 71 | A1=A2=A3=1, WE3=1, WD3=99 준비, 에지 전 | 10 | 10 |
| C09 | 76 | 75ns 상승 에지의 NBA 갱신 후 | 99 | 99 |
| C10 | 86 | x0←FFFFFFFF 시도, A1=0, A2=1 | 0 | 99 |
| C11 | 91 | 쓰기 금지, A1=1, A2=0 | 99 | 0 |
| C12 | 106 | 105ns 에지에서 x31←A5A55A5A | A5A55A5A | 99 |
| C13 | 113 | 112ns에 RESET을 올려 115ns 상승 에지 전에 검사 | 0 | 0 |
| C14 | 126 | 120ns에 RESET 해제, 125ns 에지에서 x2←80000001 | 80000001 | 80000001 |

마지막 쓰기는 130ns 하강 에지에서 WE3를 내려 중단하고 131ns에 최종 PASS 후 종료합니다. 클럭 주기는 10ns, 상승 에지는 5+10n ns입니다.

파형은 `clk reset we3 a1 a2 a3 wd3 rd1 rd2`를 함께 보세요. C08/C09 구간에서 WD3가 99로 먼저 바뀌어도 RD1/RD2는 75ns 쓰기 에지까지 10입니다. 별도 bypass는 없습니다. C06/C07은 읽기 주소가 바뀐 후 클럭을 기다리지 않는다는 것을 보여 줍니다.

## 흔한 오답

- WE3 무시: C05에서 99로 덮어씁니다.
- 쓰기 금지 분기에 0 대입: C05에서 기존 10을 잃습니다.
- 쓰기 주소로 A1 또는 상수 사용: 읽기·쓰기 포트의 독립성을 깨뜨립니다.
- RD2에도 A1 사용: 두 읽기 포트가 독립적이지 않습니다.
- 동기 리셋만 구현: C01 또는 C13의 에지 사이 초기화를 만족하지 못합니다.
- 읽기를 순차 always에 구현: C06/C07 주소 변경 직후 값을 갱신하지 못합니다.
- WD3를 곧바로 출력에 우회 연결: 쓰기 에지 전 이전 값을 보장하지 못합니다.
- 출력 폭 또는 주소 폭 혼동: 최상위 주소/패턴 C12/C14와 파형을 확인합니다.

x0 보호와 `<=` 사용은 소스에서도 확인합니다. 14개 그룹은 대표 주소 동작 확인이며 완전한 정형검증, 32주소 전수검증, 게이트 수준 등가성 증명이 아닙니다.

## 별도 합성 레슨

레슨 1·2는 시뮬레이션과 파형만 다룹니다. 합성은 [레슨 3](../todo/lesson/03_synthesis/README_KO.md)에서 완성 REGFILE로 진행합니다. 학생이 작성한 체크포인트에는 [체크포인트 합성 안내](../DC_STEP_BY_STEP_KO.md)를 적용합니다.

학생이 열어 보는 파일 자체를 명령어 목록으로 만들었습니다.

| 파일 | 내용 |
|---|---|
| `run.sh` | build 폴더 생성, VCS 실행 두 명령 |
| `view.sh` | Verdi 실행 한 명령 |
| `run_synth.sh` | DC 실행 한 명령 |
| `setup.tcl` | 라이브러리 읽기, 폴더·WORK 준비 |
| `scripts/library_setup.tcl` | target/link library 설정 두 명령 |
| `synth.tcl` | 환경 설정 → RTL 읽기 → 조건 → 합성 → 저장 → exit |

쉘/Tcl 파일에는 if/for/foreach/while/proc/catch, 해시 검사, 자체 PASS 마커가 없습니다. 각 스크립트는 해당 파일의 폴더에서 실행합니다. 학생은 DC에서 환경만 `source setup.tcl`로 읽고 나머지 명령은 한 줄씩 입력합니다. checkpoint의 명령 파일은 `synth/scripts/synth.tcl`입니다.

레슨 3의 입력은 `REGFILE.v`, 체크포인트 합성의 입력은 `../rtl/REGFILE.v`입니다. 두 위치 모두 자기 RTL을 읽습니다. 명령 결과는 해당 폴더의 `results`와 `reports`에 저장합니다.

## 학생과 확인할 것

- 현재 시뮬레이션의 PASS를 보고 파형을 엽니다. 이전 파형이나 로그를 현재 성공으로 판단하지 않습니다.
- `check_design` 성공, `report_units`의 ns/fF, 합성 후 `is_mapped=true`를 확인합니다. Error/Fatal/FAIL이면 멈춥니다.
- 넷리스트의 셀 연결 하나, area 보고서의 Total cell area, timing 보고서의 slack 부호만 찾습니다.
- slack은 표시된 한 경로의 시간 여유입니다. 전체 타이밍 만족이나 기능 등가성을 뜻하지 않습니다.
- 합성은 비채점이며 최적화·독자적 제약 작성·추가 제출을 요구하지 않습니다. 상세 STA는 7주차입니다.
- 완료 시 `exit`로 DC를 종료합니다. 긴 출력의 `--More--`는 Space, Linux `less`는 q로 다룹니다.

제작자용 자동 검증과 배포 코드는 학생 패키지 밖의 `W06_tools`에 있습니다. 학생 스크립트에 그 코드를 숨기거나 호출하지 않습니다. 실제 검증 범위는 [VALIDATION.md](VALIDATION.md)에 기록합니다.

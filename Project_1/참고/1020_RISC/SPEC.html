CPU(CORE) 면적·전력·최대 주파수는 서버 DC 합성 뒤에 채운다. 세 프로그램은 모두 같은 CPU에서 돈다.

1결정사항

  1. D1단일 사이클 CORE, CORE.v 무수정 계약은 "선택 명령 구현에 필요한" 내부 변경만 허용한다. 파이프라인이나 레지스터파일 개조는 PASS 관문(제어·연결·ISA)에서 해석이 갈릴 수 있다. 기능 FAIL은 0점이므로 가장 안전한 쪽을 택했다.
  2. D2기본 8개 명령만 사용, 선택 RV32I 미구현 비트 직렬 곱의 비용은 W doubling(28/i)과 비트 검사(16/i)다. SLLI/SRAI/BGE를 써도 둘 다 1명령=1cycle이라 줄지 않는다(§2.3). 선택 명령은 공식 어셈블러, 단독시험 제출, 채점기 주입 검사가 따라붙고 디코더 면적만 늘린다.
  3. D3곱셈 = X 비트 직렬 + W doubling, 부호비트는 뺄셈 X 한 개의 비트 검사를 4개 행이 공유해 (i,j) 쌍당 약 10 cycle. 32비트 부호확장 word라 X = −128·x₇ + Σ 2ᵏxₖ (k=0..6)를 그대로 쓰면 부호 분기 없이 bit 7만 sub 한다.
  4. D4곱한 즉시 누산, SCRATCH 미사용, 누산기 초기값 = BIAS 기준본의 SCRATCH 저장·재읽기 64회와 bias 합산 루프를 없앤다. store는 Y 4회 + DONE 1회뿐이다.
  5. D5프로그램 2종 준비: int8_fast(기본) / int8_small(대안) T 배점이 2배라 cycle이 24% 적은 fast가 유리하다. 다만 256-word IMEM은 면적 +18.6k µm², 정적전력 +0.37 mW를 더한다. 최종 선택은 §2.5 산식에 서버 측정값을 넣어 정한다.
  6. D6선언 주파수 = setup·hold STA를 모두 통과하는 최대 f T는 1/f에 비례(배점 12.5). 메모리 정적전력(약 1.2~1.6 mW)은 f와 무관하고 동적전력만 f에 비례(배점 6.25). f를 올릴수록 점수가 오른다.
  7. D7합성 대상 = CORE (CONTROLLER 포함) TOP은 배선과 시뮬레이션용 IMEM/DMEM($readmemh)이라 합성할 수 없다. SRAM 비용은 계약 산식으로 더한다(tools/summarize.py).
  8. D8SDC는 지난 학기 구조(입출력 지연 = 주기 40%)를 변수화 공식 SDC가 아직 없다. syn/CORE.sdc의 PERIOD, IO_FRAC만 바꾸면 된다. 조교가 주면 그 파일로 교체한다.
  9. D9testbench 무수정, 검증은 3단 ① Python ISA 모델 16 case(정답·쓰기범위·입력보존·DONE 순서) ② RTL 16 case × 3 프로그램 ③ CONTROLLER 디코드 34 벡터(불법 23종 → ILLEGAL=1, 쓰기 0).
  10. D10멀티코어 안 함 TOP 고정 포트에 단일 포트 IMEM/DMEM이 1개씩이라 코어 2개가 메모리를 공유하지 못한다. 면적은 2배인데 T는 최대 1/2이고, 소프트웨어만으로 이미 ×14.7이다.

2.1계산·메모리 계약

  • Y[j] = BIAS[j] + Σᵢ X[i]·W[j][i], i=0..7, j=0..3. X ∈ [−128, 127], W ∈ [−127, 127], 각 값은 32비트 부호확장 word.
  • 0x300 설정 블록을 매 실행 읽는다. 주소를 코드에 고정하지 않는다.
  • 쓰기 허용 영역은 Y(4 word), SCRATCH(32 word), DONE_ADDR. Y 4개를 다 쓴 뒤 마지막 store가 DONE_TOKEN.
  • W는 row-major: W[j][i] 주소 = W_BASE + (8j + i)·4. i를 고정하면 행 간격이 32바이트라 lw 오프셋 0/32/64/96 으로 읽는다.

2.3소프트웨어

두 프로그램(sw/int8_fast.s, sw/int8_small.s)은 같은 알고리즘이다.

acc_j ← BIAS[j]                       (j = 0..3)
for i in 0..7:
    x ← X[i];  w_j ← W[j][i]          lw 5회
    for k in 0..6:
        bit k == 1 이면 acc_j += w_j    and, beq, add×4
        w_j += w_j                      add×4 (doubling)
    bit 7 == 1 이면 acc_j −= w_j       −128·W, 부호 비트
Y[j] ← acc_j
DONE_ADDR ← DONE_TOKEN                마지막 store
프로그램구조word
int8_fasti 루프 2개씩 펼침(4회), 비트 루프 완전 전개192
int8_small비트 0..6을 루프로 접음(마스크 doubling, 128과 비교)48

cycle 산식 (RTL 측정과 일치)

fast  = 432 + 4·Σᵢ popcount(X[i] & 0xFF)
small = 609 + 4·Σᵢ popcount(X[i] & 0xFF)

최악(X 전부 −1)은 fast 688 / small 865, 최선(X 전부 0)은 432 / 609 cycle.

선택 명령이 도움이 안 되는 이유

(i,j) 쌍당 비용은 W doubling 7 + 비트 검사(and+beq) 2×8/4 + 조건부 add 최대 8, 합해서 약 10~19 cycle이다.

  • SLLI는 doubling 1명령을 1명령으로 바꿀 뿐이다.
  • BGE로 부호비트를 1명령에 검사하려면 X를 slli 24로 올리고 W를 srai로 내려야 해서 총 명령 수가 같다.
  • BNE는 루프 1회당 1 cycle, 전체로 4~8 cycle만 줄인다.

검토 후 기각한 대안

  • k 외부 루프 + 누산기 Horner: W 32개를 레지스터에 못 올린다. 2행씩 나누면 루프 오버헤드 때문에 fast보다 느리다.
  • SCRATCH에 X 배수 표: 표 생성에 i당 47 cycle이 들어 이득이 없다.
  • i 4개씩 펼침: 353 word로 512 구간에 들어간다.
